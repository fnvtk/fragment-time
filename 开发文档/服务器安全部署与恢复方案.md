# 服务器安全部署与恢复方案

## 根因

此前使用 `pkill -f next-server` 重启碎片时间后台，匹配到了同一台 KR 宝塔上的其他 Next.js 项目，造成多个 Node 项目被停止。此方式永久禁止使用。

## 新规则

1. 宝塔 Node 项目状态优先通过宝塔 API 查询。
2. 碎片时间后台只允许操作项目名 `fragment_time_admin`、目录 `/www/wwwroot/self/fragment-time-admin`、端口 `3120`。
3. API 不可用时，只能查找端口 3120 的 PID，并核对 `/proc/PID/cwd` 必须等于碎片时间目录，才允许停止该 PID。
4. 禁止 `pkill next-server`、`killall node`、按模糊名称批量重启和全局清理端口。
5. 部署顺序固定为：上传代码 → `pnpm install` → `pnpm build` → 执行 `scripts/安全重启碎片时间后台.sh` → 外网接口验收。
6. 其他项目恢复必须按宝塔 Node 项目名称逐个操作，不得顺手批量重启。

## 恢复结果

- 碎片时间后台：端口 3120 已恢复，登录和核心接口正常。
- 已自动恢复：`wzdj`、`玩值大屏`、`tongzhi`、`ymao`、`zhaoping`、`zhiji`、`AITOUFA` 等项目。
- 仍需项目负责人单独处理：`hx` 缺少 `package.json`；`ai_hair` 数据库账号认证失败；`wzwb_bp`、`kr-phone`、`kr-users` 依赖/启动配置不完整；`dlmdashboard` 原启动脚本未固定端口；部分项目启动后自身报业务代码错误。
- 以上未修复项没有修改源码、数据库或密码，避免扩大影响面。
